# Aufgabe
Du hast Zugriff auf das Projekt-Repository. Erstelle eine **maschinenlesbare Zustandsaufnahme**
des Projekts als JSON. Dieses JSON wird von einem lokalen Assistenzsystem eingelesen — es wird
**nicht von Menschen gelesen** und **nicht ausgeführt**.

## Scope
Projekt: **{{PROJECT_TITLE}}**
Quellen: **{{REPO_SCOPE}}** (nur diese; keine anderen Projekte, keine privaten Mails)
Stichtag: **{{AS_OF_DATE}}**

## Ausgabe-Regeln (strikt)
1. Gib **ausschliesslich** ein JSON-Objekt aus. Keine Einleitung, keine Erklärung, kein Kommentar.
2. Halte dich **exakt** an das untenstehende Schema. Erfinde keine zusätzlichen Felder.
3. **Wenn eine Information nicht belegbar im Repo steht: lass das Feld weg.**
   Rate niemals Termine, Verantwortliche oder Status. Ein fehlendes Feld ist korrekt — ein
   erfundenes ist ein Fehler.
4. Verwende für jedes Element ein `external_ref` nach diesen **deterministischen** Regeln
   (damit wiederholte Exporte dieselben Refs erzeugen):
   - Präfix: `proj/` Projekt · `ms/` Meilenstein · `wp/` WBS-Knoten · `pd/` Pendenz
   - Danach der **Titel** in Kleinbuchstaben, Umlaute ausgeschrieben (ä→ae, ö→oe, ü→ue, ß→ss),
     nur `a–z 0–9 -`, Leerzeichen → `-`, max. 60 Zeichen.
   - Beispiel: „Begehung Serverraum" → `wp/begehung-serverraum`
   - **Wichtig:** Leite den Ref immer aus dem Titel ab, nie aus Position oder Reihenfolge.
5. Erlaubte Werte (alles andere ist ungültig):
   - `node_kind`: `phase` | `deliverable` | `task` | `subtask` | `action`
   - `status`: `todo` | `in_progress` | `blocked` | `done` | `at_risk` | `open`
   - `phase`: `init` | `konzept` | `realisierung` | `einfuehrung` | `abschluss`
   - `impact`, `likelihood`: `tief` | `mittel` | `hoch`
6. Datumsformat immer `YYYY-MM-DD`.
7. Gib bei jedem Element, das aus einem Dokument stammt, `source_hint` mit dem Dateinamen an
   (nur Dateiname, kein vollständiger Pfad, keine Zitate aus dem Inhalt).
8. Obergrenzen: max. 500 WBS-Knoten, 300 Pendenzen, je 100 Annahmen/Risiken/Entscheide.
   Bei mehr: die wichtigsten auswählen und in `meta.generator_note` vermerken.

## Schema
```json
{
  "schema": "hermes.project_state/v1",
  "meta": { "generated_at": "<ISO-8601>", "source": "m365_copilot",
            "repo_scope": "{{REPO_SCOPE}}", "generator_note": "<optional>" },
  "project": {
    "external_ref": "proj/<slug>", "title": "<string>", "goal": "<1-3 Sätze>",
    "phase": "<enum>",
    "milestones": [ { "external_ref": "ms/<slug>", "title": "<string>",
                      "due": "YYYY-MM-DD", "status": "<enum>" } ]
  },
  "wbs": [ { "external_ref": "wp/<slug>", "parent_ref": "wp/<slug>|null",
             "title": "<string>", "node_kind": "<enum>", "status": "<enum>",
             "due": "YYYY-MM-DD", "effort_hint_h": <number>,
             "depends_on_refs": ["wp/<slug>"], "source_hint": "<Dateiname>" } ],
  "pendenzen": [ { "external_ref": "pd/<slug>", "title": "<string>", "owner": "<Rolle oder Name>",
                   "raised_by": "<string>", "due": "YYYY-MM-DD", "status": "<enum>",
                   "source": "meeting|review|decision_log|manual", "source_hint": "<Dateiname>" } ],
  "open_assumptions": [ { "text": "<string>", "since": "YYYY-MM-DD" } ],
  "risks": [ { "title": "<string>", "impact": "<enum>", "likelihood": "<enum>" } ],
  "decisions": [ { "title": "<string>", "at": "YYYY-MM-DD", "rationale": "<string>" } ]
}
```

## Qualitätsprüfung vor der Ausgabe
- Ist jedes `parent_ref` auch als `external_ref` in `wbs` vorhanden? (sonst weglassen)
- Enthält `depends_on_refs` nur existierende Refs? (sonst weglassen)
- Gibt es Zyklen in `parent_ref` oder `depends_on_refs`? (dann auflösen)
- Sind alle Enum-Werte aus der erlaubten Liste?
- Ist die Ausgabe **valides JSON** und **nur** JSON?
