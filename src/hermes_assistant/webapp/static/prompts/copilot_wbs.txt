# Aufgabe
Du hast Zugriff auf das Projekt-Repository. Erstelle einen maschinenlesbaren
PROJEKTSTRUKTURPLAN (WBS) als JSON. Dieses JSON wird von einem lokalen
Assistenzsystem (Hermes) eingelesen — es wird NICHT von Menschen gelesen und
NICHT ausgeführt. Gib ausschliesslich gültiges JSON nach dem Schema
hermes.wbs/v1 aus.

Hinweis: Dieser eine Export speist ZWEI Ansichten — den Strukturplan (WBS,
verschachtelt nach parent_ref) und das Kanban-Board (gruppiert nach status).
Es gibt bewusst keinen separaten Kanban-Export: beides sind Darstellungen
derselben Aufgaben.

## Scope
Projekt: {{PROJECT_TITLE}}
Quellen: {{REPO_SCOPE}} (nur diese Quellen; keine anderen Projekte, keine
privaten Mails, keine Screenshots, keine Bilder)
Stichtag: {{AS_OF_DATE}}

## Ausgabe-Regeln (strikt)
1. Gib AUSSCHLIESSLICH ein einzelnes JSON-Objekt aus. Keine Einleitung, keine
   Erklärung, keine Markdown-Code-Fences. Erstes Zeichen "{", letztes "}".
2. Halte dich EXAKT an das Schema. Keine zusätzlichen, keine umbenannten Felder.
3. Nicht belegbare Information: Feld weglassen. Rate niemals Status oder
   Verantwortliche. Ein fehlendes optionales Feld ist korrekt — ein erfundener
   Wert ist ein Fehler.
4. external_ref DETERMINISTISCH aus dem Titel bilden (damit wiederholte
   Exporte keine Duplikate anlegen):
   - Präfix "wp/", danach der Titel in Kleinbuchstaben, Umlaute ausgeschrieben
     (ä→ae, ö→oe, ü→ue, ß→ss), nur a–z 0–9 -, Leerzeichen → -, max. 60 Zeichen.
   - Beispiel: „Begehung Serverraum" → wp/begehung-serverraum
   - IMMER aus dem Titel ableiten, nie aus Position oder Reihenfolge.
5. Erlaubte Enum-Werte (jeder andere Wert ist ungültig):
   - node_kind: phase | deliverable | task | subtask | action
   - status:    open | in_progress | done | blocked      ← NUR diese vier
6. Baumstruktur über parent_ref:
   - Wurzelknoten: parent_ref weglassen oder null.
   - Jedes parent_ref MUSS entweder als external_ref eines anderen Knotens in
     DIESEM Export vorkommen oder aus einem früheren Import bereits bekannt
     sein. Zeigt es auf nichts davon, wird der Import abgelehnt.
   - KEINE Zyklen. Die Reihenfolge im Array ist egal — Kinder dürfen vor
     ihren Eltern stehen.
   - Jedes external_ref darf im Export nur EINMAL vorkommen. Kürze lange Titel
     so, dass keine zwei Knoten denselben Slug ergeben.
7. Obergrenze: max. 500 Knoten. Bei mehr: die wichtigsten auswählen.
8. Nachlieferungen sind erlaubt: Du darfst einen Teilbaum exportieren und ihn
   über parent_ref an einen bereits importierten Knoten hängen.

## Schema
{
  "schema": "hermes.wbs/v1",
  "meta": { "generated_at": "<ISO-8601>", "source": "m365_copilot",
            "repo_scope": "{{REPO_SCOPE}}" },
  "project_ref": "proj/<slug>",
  "wbs": [
    { "external_ref": "wp/<slug>",
      "parent_ref": "wp/<slug> oder weglassen",
      "title": "<Titel des Arbeitspakets>",
      "node_kind": "phase|deliverable|task|subtask|action",
      "status": "open|in_progress|done|blocked",
      "owner": "<Rolle oder Name, optional>" }
  ]
}

## Beispiel (gültig — validiere deine Struktur dagegen)
{
  "schema": "hermes.wbs/v1",
  "meta": { "generated_at": "2026-08-22T10:00:00Z", "source": "m365_copilot",
            "repo_scope": "Webshop-Relaunch" },
  "project_ref": "proj/webshop-relaunch",
  "wbs": [
    { "external_ref": "wp/realisierung", "title": "Realisierung",
      "node_kind": "phase", "status": "in_progress" },
    { "external_ref": "wp/checkout-implementieren", "parent_ref": "wp/realisierung",
      "title": "Checkout implementieren", "node_kind": "task",
      "status": "in_progress", "owner": "Technik" },
    { "external_ref": "wp/zahlungsanbieter-anbinden", "parent_ref": "wp/realisierung",
      "title": "Zahlungsanbieter anbinden", "node_kind": "task", "status": "blocked" },
    { "external_ref": "wp/abnahme", "title": "Abnahme",
      "node_kind": "deliverable", "status": "open" }
  ]
}

## Checkliste (vor der Ausgabe abarbeiten)
[ ] Ausgabe ist EIN JSON-Objekt, beginnt mit { und endet mit }.
[ ] "schema" ist exakt "hermes.wbs/v1".
[ ] Jeder status ist open|in_progress|done|blocked.
[ ] Jeder node_kind ist phase|deliverable|task|subtask|action.
[ ] Jedes parent_ref existiert in diesem Export oder ist bereits importiert.
[ ] Keine Zyklen in parent_ref.
[ ] Jedes external_ref ist eindeutig und aus dem Titel abgeleitet.
[ ] Kein external_ref kommt zweimal vor.

## Häufige Fehler (unbedingt vermeiden)
- KEINE Markdown-Code-Fences (``` ) um das JSON.
- KEINE erklärenden Sätze vor oder nach dem JSON.
- KEIN parent_ref auf einen Knoten, den es weder in diesem Export noch aus
  einem früheren Import gibt — der gesamte Import wird dann abgelehnt.
- KEIN doppeltes external_ref — der Import wird abgelehnt, damit kein Knoten
  unbemerkt verloren geht.
- KEINE Status-Werte wie "todo", "wip" oder "at_risk".
- KEINE verschachtelten "children"-Arrays — die Hierarchie entsteht
  ausschliesslich über parent_ref in einer flachen Liste.
